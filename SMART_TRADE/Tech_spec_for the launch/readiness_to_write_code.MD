## Почему не 100%

Спецификация очень сильная по архитектуре, модулям, процессам и инвариантам.
Но для режима **«просто писать код как исполнитель, без уточнений»** всё ещё не хватает нескольких **конкретных входов внедрения** (операционных, интеграционных и environment-level).

Ключевая причина:
- есть детальное **что** и **как логически**,
- но не везде зафиксировано **с чем именно подключаться в вашей среде** (какие endpoint’ы, какие provider’ы, какие конкретные лимиты/секреты/параметры запуска).

## Что нужно от вас, чтобы довести готовность до 100%

Ниже — только то, без чего придётся гадать.

### 1) Execution bridge: точный внешний контракт

Укажите, пожалуйста:
- базовый URL execution-bridge;
- список endpoint’ов (submit/cancel/status/fills/webhooks);
- формат auth (header/signature/token);
- idempotency ключ и правило его генерации;
- единый формат ошибок (code/message/retryable).

### 2) Market data providers: конкретный источник и payload

Нужно зафиксировать:
- основной провайдер (или несколько с приоритетом);
- schema входных данных для candles/spread/liquidity/execution telemetry;
- frequency/SLA и допустимые задержки;
- fallback policy при деградации feed.

### 3) OpenClaw runtime integration: фактический API-профиль

Нужно явно определить:
- версию OpenClaw/runtime profile, с которой работаем;
- точные команды/роуты materialize workspace, spawn session, hooks;
- ограничения sandbox/FS/network для агентных сессий;
- policy по retries/timeouts на вызовах OpenClaw.

### 4) Production config baseline (обязательные значения по умолчанию)

Нужен один утверждённый `config baseline` для MVP:
- таймауты (entry_timeout_sec, case TTL, webhook timeout);
- risk limits (max concurrent cases, exposure limits, stop rules);
- feature flags (что включено/выключено в MVP);
- значения scheduler cadence (частота jobs).

### 5) Источник “истины цены” для replay/метрик

Чтобы не было расхождений в аналитике:
- зафиксируйте единый источник mark/last/mid для расчётов;
- правила при отсутствии тика/дырках данных;
- canonical rounding/precision policy по символам.

### 6) Secrets и контур среды (минимум для первого запуска)

Нужен список обязательных env переменных для окружения:
- execution secrets;
- LLM keys + fallback;
- source-policy allowlist/denylist;
- OpenClaw runtime creds/paths.

(Можно одним финальным файлом `env_contract.md` + `.env.example` c реальными именами переменных.)

### 7) Критерии приёмки “готово к прод-пилоту”

Нужно явно согласовать:
- минимальный набор интеграционных тестов;
- smoke/e2e сценарии, которые обязаны проходить;
- пороги отказа/rollback;
- формат release checklist для каждого PART.
