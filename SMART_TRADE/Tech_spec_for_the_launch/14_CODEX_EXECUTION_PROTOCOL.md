# 14_CODEX_EXECUTION_PROTOCOL

## Назначение

Этот файл задаёт протокол, по которому Codex должен выполнять части проекта.

---

## 1. Формат запроса к Codex

Шаблон запроса:

```text
Используй архив SMART_TRADE как единственный источник истины.
Реализуй PART <NN> из файла 13_CODEX_PARTITION_PLAN.md.

Обязательные правила:
1. Не меняй проектную логику.
2. Не упрощай спецификацию.
3. Работай только в пределах PART <NN>.
4. Если нужен код-основание — сначала смотри CODE_SKELETON_PACK и 02_OPENSPACE_DONOR_MAP.md.
5. Обнови PART_STATUS.md, CHANGELOG.md, TODO.md.
6. Ничего не удаляй.
7. По завершении выдай:
   - список созданных/изменённых файлов
   - что реализовано
   - что осталось
   - какие тесты запустить
```

---

## 2. Что Codex должен сделать в каждой части

### 2.1. Перед кодом
- прочитать `00_README.md`
- прочитать `01_SMART_TRADE_MASTER_SPEC_MAX.md`
- прочитать `11_MAX_APPROVED_FEATURE_APPENDIX.md`
- открыть нужную часть в `13_CODEX_PARTITION_PLAN.md`
- открыть нужные разделы в `CODE_SKELETON_PACK/`

### 2.2. Во время кода
- работать только в своей части
- не трогать unrelated modules
- не переименовывать канонические сущности
- не менять contract semantics

### 2.3. После кода
- обновить `PART_STATUS.md`
- обновить `CHANGELOG.md`
- обновить `TODO.md`
- перечислить manual follow-up, если есть

---

## 3. Что считается ошибкой Codex

1. Появление `NO_TRADE` как пользовательского решения.
2. Смешивание capital logic с signal quality.
3. Использование phenotype как подсказки пустому агенту.
4. Превращение `expected_fill_window_sec` в kill switch.
5. Удаление файлов из архива.
6. Смешивание production и lab lanes.
7. Прямая мутация протокольных навыков.
8. Игнорирование `Protocol Integrity Gate`.
9. “Всегда выбирать champion”.
10. Прямая recombination несовместимых skill lines.

---

## 4. Что считается завершением части

Часть считается завершённой только если:

- написан основной код части;
- обновлены служебные статус-файлы;
- модуль не противоречит master spec;
- перечислены тесты;
- перечислены open issues.

---

## 5. Приоритет доноров кода

Если нужен донор, порядок такой:

1. `CODE_SKELETON_PACK/`
2. `02_OPENSPACE_DONOR_MAP.md`
3. `03_OPENCLAW_AGENT_MODEL.md`
4. `04_LLM_CALL_MATRIX.md`
5. `07_AGENT_BOOTSTRAP_TEMPLATES.md`

---

## 6. Стратегия написания под ~5000 строк

Codex не должен пытаться:
- дописать соседнюю часть “заодно”;
- преждевременно строить advanced polish;
- делать масштабный рефакторинг прошлых частей.

Правильная стратегия:

```text
implement exact slice -> stabilize -> document -> stop
```
